01 / CORE MOTIVATION

The Digital Footprint Crisis & DPDP Context

🚨

1. Data Sprawl Across 50+ Web Services

Users register on dozens of e-commerce, media, and forum sites over time, leaving sensitive identifiers (Name, Email, Phone) scattered across legacy databases without tracking.

👁️‍🗨️

2. Invisible & Opaque Consents

Pre-checked boxes and 40-page legal terms trick users into granting broad consent for marketing, tracking, and 3rd-party data sharing with zero visibility.

⚖️

3. Unenforceable Deletion Rights

The DPDP Act 2023 guarantees §6 Revocation and §12 Erasure, but users lack simple, consolidated tools to enforce these rights across fragmented web platforms.

📜

4. Absence of Audit-Ready Evidence

When users request account deletion via email or web forms, organizations rarely provide verifiable logs, leaving individuals without proof of legal compliance.

04 / TECHNICAL BREAKTHROUGH

The Honest 3-Tier Deletion & Revocation Model

LEVEL 1 — DIRECT API

Partner Endpoint Integration

  • Used when target website exposes an official privacy API.
  • Platform calls POST /api/partner/revoke or /delete.
  • Status updates instantaneously to REVOKED / COMPLETED.
  • Fully validated in demo via ShopEase backend integration.
LEVEL 2 — GUIDED URL

Authenticated Redirection Drawer

  • Used when site requires manual login & account navigation.
  • Platform opens a guided side-drawer with direct deep link.
  • Provides step-by-step UI directions for deletion.
  • Eliminates searching through complex settings menus.
LEVEL 3 — LEGAL NOTICE

DPDP §6 / §12 Generator

  • Used when target website lacks public deletion APIs.
  • Generates structured legal demand citing DPDP Act 2023.
  • Triggers pre-filled mailto: or copyable legal transcript.
  • Registers request in Request Tracker for SLA tracking.

06 / EXTENSION ENGINEERING

Browser Extension Architecture & Security Mandate

Extension Execution Pipeline

1
Passive DOM Interception (content.js)

Attaches non-blocking listeners to HTML form submit events across all visited web domains.

2
Form & Consent Inspection

Identifies input fields (Email, Phone, Name) and checkboxes containing terms/marketing keywords.

3
Payload Dispatch (background.js)

Sends sanitized metadata payload via async HTTP POST /api/events to central backend.

4
Extension Popup View (popup.jsx)

Displays instant domain privacy status, detected fields, and active consents to the user.

🛡️ Zero Credential Retention Mandate

STRICT EXCLUSION RULES
  • Passswords Completely Ignored: input[type="password"] strictly excluded.
  • Payment Cards Ignored: Credit card, CVV, and banking fields stripped out.
  • OTP & Auth Tokens Ignored: Security verification codes never processed.
PRIVACY BY DESIGN
  • Category Level Metadata: Logs data types ("Email Present") rather than raw text strings.
  • Environment Isolation: API keys isolated exclusively in backend .env.
  • Transparent Execution: Open content script execution visible in DevTools.
07 / PRIVACY INTELLIGENCE

AI Policy Summarizer & Privacy Score Algorithm

🤖 Gemini API Policy Summarizer

Problem Solved

Privacy policies average 4,000 words of legal jargon that no consumer reads.

Gemini AI Prompt Engineering

Extracts key data practices into 2 plain-English sentences: (1) What data is collected, (2) How data is shared or sold.

Rule-Based Graceful Fallback

If Gemini API key is missing or offline, system switches to structured keyword extraction without breaking UI.

📊 Dynamic Privacy Score Equation

Score = 100 - (ActiveMarketing × 5) - (HighRiskSites × 10) + (RevokedConsents × 3)
Base Score: 100

Starting score for clean digital footprint.

Marketing Deductions (-5 pts)

Subtracted for each active promotional / 3rd party consent.

High Risk Site Penalty (-10 pts)

Deducted for accounts on unverified or data-broker domains.

Revocation Bonus (+3 pts)

Rewarded immediately when user revokes consent or submits erasure.

❓ Committee Q&A Readiness

Q: How do you handle password safety?

A: Password inputs (type="password") and credit card fields are strictly filtered at content script layer and never leave the DOM.

Q: Why not auto-delete on all sites?

A: Universal auto-deletion is impossible due to auth & CSRF. Our 3-tier engine provides an honest, reliable alternative.

Q: How does this align with DPDP 2023?

A: Directly enforces Data Principal rights under §6 (Consent Withdrawal) & §12 (Data Erasure) with timestamped audit logs.
