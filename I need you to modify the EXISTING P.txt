CRITICAL RISK ENGINE CORRECTION — CURRENT SYSTEM IS TOO NAIVE

The current implementation of the PrivacyLens / RECLAIM risk engine is NOT working correctly for real-world websites.

I tested it on piracy/unofficial streaming websites such as:

net77.cc
and other similar unofficial streaming websites.

The extension displayed:

CLEAN / LOW RISK

even though these websites are exactly the type of sites where we want the product to identify elevated privacy exposure.

The reason is clear from the current architecture:

The existing engine primarily scores visible DOM signals such as:

- HTTP
- Password field
- Phone field
- DOB
- Email
- Name
- Marketing checkbox
- Tracker scripts
- Privacy policy

Therefore, a website can have:

HTTPS
No login form
No phone field
No DOB field

and still receive a very low score.

THIS IS NOT SUFFICIENT.

We need to redesign the RISK DETECTION LOGIC while preserving the existing UI, website tracking, exposure tracking, realtime synchronization, and popup behavior.

============================================================
1. CORE PROBLEM
============================================================

The current engine answers:

"Does this page currently contain certain privacy-related HTML elements?"

But our product needs to answer:

"How much privacy exposure should a user be concerned about when interacting with this website?"

These are different questions.

Therefore create a MULTI-LAYER PRIVACY RISK ENGINE.

============================================================
2. NEW RISK ENGINE ARCHITECTURE
============================================================

The final score should be calculated from:

A. CONNECTION SECURITY
B. DATA COLLECTION
C. CONSENT / PRIVACY TRANSPARENCY
D. TRACKING / THIRD-PARTY BEHAVIOR
E. WEBSITE BEHAVIOR
F. WEBSITE CATEGORY / DOMAIN INTELLIGENCE
G. SUSPICIOUS NAVIGATION / AD BEHAVIOR
H. ACCOUNT / EXPOSURE INFORMATION

Conceptually:

                WEBSITE
                   |
        ┌──────────┼──────────┐
        ↓          ↓          ↓
 Connection     Page       Behavior
  Signals      Signals      Signals
        ↓          ↓          ↓
        └──────────┼──────────┘
                   ↓
           Domain Intelligence
                   ↓
             Risk Engine
                   ↓
           SCORE 0–100
                   ↓
       LOW / MEDIUM / HIGH
                   ↓
          EXPLAINABLE REASONS

============================================================
3. IMPORTANT — DO NOT USE AI FOR THE FINAL SCORE
============================================================

The final risk classification MUST remain deterministic.

AI can later explain the result in natural language.

But:

AI MUST NOT randomly decide:

"this website looks dangerous."

The actual score must come from predefined rules.

This makes the system:

- Explainable
- Reproducible
- Debuggable
- Suitable for a hackathon
- Easy to demonstrate to judges

============================================================

Detect observable behavior such as:

- Excessive popup windows
- Pop-under behavior
- Unexpected new tabs/windows
- Repeated redirects
- Automatic navigation to another domain
- Multiple advertisement overlays
- Forced external navigation
- Download prompts
- Notification permission requests

Scoring:

+10

+15

+10

+10

Notification permission request:
+8

+15

These are PRIVACY EXPOSURE / BROWSER BEHAVIOR signals.

Do NOT call the website malware simply because these signals exist.
