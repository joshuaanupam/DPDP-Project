IMPLEMENTATION TASK — PRIVACY RISK FLAGGING + SMART EXTENSION POPUP

We need to add a deterministic, hardcoded website risk-classification system to the existing PrivacyLens / RECLAIM project.

IMPORTANT:

DO NOT redesign the existing UI.

DO NOT replace the current extension popup.

DO NOT remove existing features.

DO NOT use AI/LLM to determine the risk level.

The risk classification must be based on a transparent, predefined rule engine so that we can explain to hackathon judges exactly why a website received a particular risk level.

============================================================
1. OBJECTIVE
============================================================

Every website detected by the browser extension must receive a privacy/security risk classification:

LOW
MEDIUM
HIGH

The extension should analyze observable privacy/security signals from the current website and calculate a deterministic risk score.

The result should be displayed in:

1. Browser extension popup
2. Website risk notification popup
3. Dashboard website records
4. Website detail page where applicable

The same risk result must be used everywhere.

There must be ONE risk calculation engine.

Do NOT create separate risk logic for extension and dashboard.

============================================================
2. IMPORTANT TERMINOLOGY
============================================================

This is a:

"Privacy Exposure Risk"

It should NOT be presented as:

"This website is malicious."

It should NOT claim:

"This website is unsafe."

unless there is actual evidence.

Instead use language such as:

"High Privacy Exposure"

"Medium Privacy Exposure"

"Low Privacy Exposure"

The risk is based on the privacy/security signals that our extension can observe.

Example:

HIGH PRIVACY EXPOSURE

Reasons:
- Website uses HTTP for credential submission
- Requests phone number
- Requests date of birth
- Contains marketing consent
- Contains multiple third-party trackers

This is much more defensible.

============================================================
5. RULE DETAILS
============================================================

RULE 1 — HTTP

If the current page is using:

http://

instead of:

https://

add:

+30 risk points.

Reason:

Data transmitted over an unencrypted HTTP connection may be exposed.

------------------------------------------------------------

RULE 2 — PASSWORD OVER HTTP

If a password input exists AND the page is using HTTP:

+40

This is a critical privacy/security warning.

Reason:

Credential submission over an unencrypted connection is a serious risk signal.

This should be one of the strongest rules.

------------------------------------------------------------

RULE 3 — EMAIL COLLECTION

If the website collects an email address:

+5

Reason:

Email is personal information.

Do NOT consider email collection alone to be high risk.

------------------------------------------------------------

RULE 4 — PHONE COLLECTION

If the website requests a phone number:

+10

Reason:

Phone number is additional personal information.

------------------------------------------------------------

RULE 5 — NAME COLLECTION

If the website requests a name:

+3

------------------------------------------------------------

RULE 6 — ADDRESS COLLECTION

If the website requests:

- Address
- Home address
- Shipping address

add:

+10

------------------------------------------------------------

RULE 7 — DATE OF BIRTH

If the website requests:

- Date of birth
- DOB
- Birth date

add:

+15

------------------------------------------------------------

RULE 8 — FINANCIAL INFORMATION

If the page visibly requests:

- Card information
- Bank account information
- Payment information

add:

+20

IMPORTANT:

DO NOT CAPTURE THE ACTUAL FINANCIAL INFORMATION.

Only detect the presence/type of the field.

Never store:

card number
CVV
bank credentials
UPI PIN
payment credentials

------------------------------------------------------------

RULE 9 — MARKETING CONSENT

If the website asks for marketing/promotional consent:

+8

Example:

"Receive promotional emails"

"Send me offers"

"Subscribe to marketing"

------------------------------------------------------------

RULE 10 — THIRD-PARTY DATA SHARING

If the website visibly indicates that information may be shared with:

- Partners
- Advertisers
- Third parties
- Service providers

add:

+15

Only flag this if there is an observable indication.

Do NOT assume every third-party script means data sharing.

------------------------------------------------------------

RULE 11 — THIRD-PARTY TRACKERS

If multiple recognizable third-party tracking/analytics domains are detected:

+10

For the hackathon MVP maintain a small hardcoded list.

Example categories:

analytics
advertising
tracking

Do not attempt to create a perfect tracker database.

This is only a heuristic.

------------------------------------------------------------

RULE 12 — NO PRIVACY POLICY DETECTED

If a website appears to collect personal information but no obvious privacy policy link is detected:

+10

Look for links containing terms such as:

privacy
privacy-policy
data-policy

IMPORTANT:

"No privacy policy detected" means:

"Our extension could not find an obvious privacy policy link."

Do NOT claim:

"This website has no privacy policy."

------------------------------------------------------------

RULE 13 — BROAD CONSENT

If the website has broad consent wording such as:

"I agree to all purposes"

"I agree to receive marketing"

"I agree to share my data"

or multiple purposes bundled into a single consent:

+10

------------------------------------------------------------

RULE 14 — EXCESSIVE DATA COLLECTION

If a form requests an unusually large number of personal data fields:

+8

For example:

Name
Email
Phone
DOB
Address
Gender
Location
Occupation
etc.

Use a simple threshold such as:

5+ personal data fields

Do not treat this as proof of malicious behavior.

It is simply a privacy exposure indicator.

------------------------------------------------------------

RULE 15 — CROSS-SITE IFRAME

If the website embeds multiple external frames from different domains:

+5

This is only a minor signal.

score = sum(rule points)

score = Math.min(score, 100)

27. PRIVACY / SECURITY REQUIREMENTS
============================================================

The extension must NOT collect:

- Password values
- OTP values
- Credit card numbers
- CVV
- Bank passwords
- Authentication tokens
- Session cookies

============================================================
28. PERFORMANCE
============================================================

Risk analysis must not make websites slow.

Do not continuously scan the entire DOM every few milliseconds.

Use:

- Initial scan
- MutationObserver only where required
- Debouncing
- Lightweight selectors
- Limited scanning frequency

Avoid expensive processing.
